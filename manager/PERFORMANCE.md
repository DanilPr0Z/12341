# Оптимизация производительности Manager Panel

## Проблема: Высокое потребление памяти (1GB на вкладку)

### Причины:
1. **Загрузка всех данных сразу** - без пагинации
2. **Множество Chart.js графиков** - особенно на странице Analytics
3. **FullCalendar** - тяжелая библиотека для расписания
4. **Утечки памяти** - графики не уничтожались при обновлении

---

## ✅ Уже реализовано:

### 1. Лимиты на выборку данных
- Бронирования: **100 последних записей** вместо всех
- Пользователи: **100 последних записей** вместо всех
- Для полного списка используется экспорт в CSV

**Изменено в:** `manager/views.py`
```python
bookings = Booking.objects...[:100]  # Лимит 100
users = User.objects...[:100]        # Лимит 100
```

### 2. Правильная очистка графиков
- Графики теперь уничтожаются перед созданием новых
- Предотвращает утечки памяти при обновлении данных

**Изменено в:** `manager/templates/manager/dashboard.html`
```javascript
if (revenueChart) {
    revenueChart.destroy();
    revenueChart = null;
}
```

### 3. UI индикаторы лимитов
- Добавлены пометки "(последние 100)" в заголовках таблиц
- Кнопки "Экспорт всех" для получения полных данных

## 🔧 Дополнительные рекомендации:

### Если память всё ещё проблема:

1. **Отключить страницу Analytics временно**
   - Самая тяжелая страница (5-6 графиков)
   - Открывать только когда нужна аналитика

2. **Уменьшить лимиты еще больше**
   ```python
   # В manager/views.py
   bookings = Booking.objects...[:50]   # Было 100
   users = User.objects...[:50]         # Было 100
   ```

3. **Lazy loading для Chart.js**
   - Загружать Chart.js только на страницах где он нужен
   - Сейчас загружается в base.html для всех страниц

4. **Отключить FullCalendar на Schedule**
   - Заменить на простую HTML таблицу
   - FullCalendar очень тяжелый (~500kb библиотека)

5. **Использовать CDN версии библиотек**
   - Включить кеширование браузера
   - Сейчас уже используется, но можно добавить версионность

## 🚀 Радикальные оптимизации (если нужно):

<!-- Простая таблица вместо интерактивного календаря -->

**Экономия:** ~200-300MB памяти

- Легче чем React/Vue
- Реактивность из коробки
- ~15kb вместо тяжелых фреймворков

## 🔍 Мониторинг памяти:

Открой DevTools → Memory → Take snapshot

Проверь что больше всего жрёт память:
- `Chart` объекты
- `FullCalendar` объекты
- DOM nodes (если много)
- Listeners (если не удалились)
